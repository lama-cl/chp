## Agent notes

Written by the implementing agent; check them like anything else.

- Scope: reporting only. P0 adds `subject.escape` and `indirectCallSites` to paper facts (schema v10) and `indirectCallSites` to the report. No analysis path reads them.
- Equivalence check: all 87 `examples/*.c` plus the 11 original fixtures were run with the pre-P0 and final P0 builds (text output, link summary, report, paper facts = 384 files). After removing the two new fields and the version number, every file is byte-identical / JSON-equal.
- `escape` is evidence, not a verdict. A subject can be typed and still escape (it is then bucketed `resolved`). `reasons` lists every reason; `reason` is the first. Each site has a kind: `external`, `project`, `indirect-external` or `indirect`.
- Self-review of the first packet found three accounting errors, now fixed and covered by fixture checks: (1) 87 of 950 corpus escapes said `external-unmodeled` with no callee. They were arguments to project functions in other TUs, which the pre-existing `externalBoundary` flag treats as external because it consults only the current TU. These are now `forwarded-to-project` with the callee named (`escape_cross_tu/`). (2) Indirect calls whose target is known but external (parson `parson_free` = `free`) were reported as unresolved callbacks; they are now `external-unmodeled` via `free`, site kind `indirect-external` (`ext_indirect_external.c`). (3) zlib `inflateBack::in_desc` was blocked with no reason; added `callback-formal` (`ext_formal_callback.c`).
- Existing soundness gap, not fixed in P0: a global function pointer is resolved from its initializer only, and reassignments in other functions are ignored (parson: `parson_free = free`, reassigned at parson.c:2053). P0 labels these sites `global-initializer`, not `flow-sensitive`, and adds the red gate `P1-fp-global-reassigned`, so P1 must fix it.
- Known limitation: escape sites inside macros point at the macro's spelling location (binn: `#define strnicmp strncasecmp`). The tool's `sourceSpan` uses spelling locations everywhere; switching to expansion locations would change every output, so it should be its own change.
- Library functions the tool already treats as memory/string sinks (`memcpy`, `strlen`, ...) have their own pointer-use kind and are not recorded as escapes. Revisit in P4.
- Corpus limits: lua-5.4.1 is excluded by default because `build_summary_index.py` needs more than 25 minutes on its 94 MB of summaries (a pre-existing problem, worth fixing before P1, since lua is the richest function-pointer project). vsftpd `sysdeputil.c` needs PAM headers that are not installed here. thttpd needs configure-equivalent defines and two generated headers, which are in `corpus-include/`.
- Pre-existing, not P0: `validate_paper_facts.py` rejects hiredis `test.c` for a duplicate `declarationId` (`sds.h:89:44`, an inline function in a header). The pre-P0 build produces the same error. All other corpus and fixture paper facts validate.
